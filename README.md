# Altropos

Altropos - веб-приложение для поиска ответов во внутренних документах МФТИ. Вместо ручного просмотра регламентов пользователь задает вопрос обычными словами и получает ответ с дословными цитатами и ссылками на документы.

Например, можно спросить, куда обратиться при потере пропуска или что происходит при нарушении срока возврата займа. Программа ищет основания в загруженных документах, указывает найденные условия и позволяет открыть оригинал для проверки.

## Что умеет программа

- Принимать PDF, DOCX, XLSX и HTML, а также импортировать выбранные документы с сайта mipt.ru.
- Извлекать текст и распознавать отсканированные страницы PDF с помощью OCR.
- Показывать полный документ в HTML, исходный файл, метаданные и предупреждения обработки.
- Искать по словам и по смыслу, в том числе при различии формулировок вопроса и документа.
- Формировать ответы с цитатами, ссылками на источники и учетом указанной даты применимости.
- Проверять состояние индекса и восстанавливать его без повторного OCR и создания дубликатов документа.
- Предоставлять администратору инструменты проверки распознавания и подтверждения метаданных. В публичном развертывании доступ зависит от роли пользователя.

## Как устроено решение

Используется RAG (Retrieval-Augmented Generation) - подготовка ответа языковой моделью на основе найденных фрагментов документов.

1. Файл поступает в фоновую очередь. Обработчик извлекает текст, при необходимости запускает OCR и разбивает содержимое на фрагменты с привязкой к страницам или блокам оригинала.
2. Для опубликованного документа создаются два поисковых индекса. BM25 ищет совпадения слов, а BGE-M3 преобразует текст в числовые векторы для поиска по смыслу через FAISS.
3. Результаты объединяются. Модель BGE reranker повторно оценивает соответствие найденных фрагментов вопросу и упорядочивает их.
4. Языковая модель семейства Qwen составляет ответ по переданным источникам. Сервер проверяет идентификаторы фрагментов и дословность цитат, затем выполняется отдельный вызов модели для смысловой проверки. При замечаниях допускается одна попытка исправления.
5. Пользователь получает ответ со ссылками либо явное сообщение об ограничениях. Если проверка не пройдена, неподтвержденные выводы не публикуются; найденные источники могут быть показаны отдельно.

В поиск попадают только опубликованные документы со статусом `ready` и согласованными индексами. Документы `needs_review` требуют проверки. Версии, фрагменты и контрольные суммы связываются между собой, чтобы ответ опирался на определенную редакцию текста.

Основной стек: Python, FastAPI, Jinja2 и JavaScript для веб-интерфейса, SQLite для хранения состояния, FAISS и BM25 для поиска, Tesseract для OCR, llama.cpp для запуска языковой модели. Модельные сервисы можно разместить на отдельной машине; обязательного обращения к облачным LLM нет.

## Быстрый локальный запуск

Нужен Python 3.11-3.13. Для OCR дополнительно нужен Tesseract с русским и английским языками. Реальные документы и веса моделей в репозиторий не входят.

Пример для Windows и PowerShell с установленным Python 3.11:

```powershell
git clone https://github.com/lonvein/altropos.git
cd altropos
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt

$env:PROFILE = "development"
$env:DATA_DIR = "runtime/local"
$env:ML_ENABLED = "false"
$env:LLM_ENABLED = "false"
$env:UI_SYNTHETIC_FALLBACK = "false"
$env:AUTH_REQUIRED = "false"
.venv\Scripts\python.exe -m uvicorn navigator.main:app --host 127.0.0.1 --port 8000
```

Откройте [локальный сайт](http://127.0.0.1:8000). Этот запуск работает с настоящими файлами, но без моделей: доступен поиск BM25, а вместо сгенерированных выводов показываются найденные источники. Пустую базу сначала нужно наполнить документами. Остановка сервера - `Ctrl+C`.

Для ответов по смыслу подключите embeddings, reranker и LLM, задав адреса сервисов и закрепленные ревизии моделей. Порядок настройки описан в [инструкции RAG](docs/rag-cycle.md). Варианты развертывания: [Docker](docs/deployment.md) и [отдельный сервер моделей с VPS](docs/deployment-laptop.md).

## Проверки и ограничения

```powershell
.venv\Scripts\python.exe -m pytest -q
git diff --check
```

Автоматические тесты используют искусственные документы и адаптеры моделей. Они проверяют обработку файлов, публикацию индексов, поиск, цитирование и поведение при ошибках. Качество настоящих моделей дополнительно проверяется на реальных вопросах; отдельные успешные ответы не означают подтвержденную точность на всем корпусе.

OCR может ошибаться, дата действия документа может требовать подтверждения, а смысловая проверка той же моделью не заменяет проверку человеком. При отключенных или недоступных сервисах программа сообщает об ограничениях. Профили и модели переключаются вручную.

Оригиналы, базы, индексы, веса и `.env` хранятся вне Git. Инструкции внутри загруженных документов обрабатываются как данные.

## Где искать код и документацию

- `navigator/ingestion/` - извлечение текста, OCR и сегментация.
- `navigator/documents/` - загрузка, импорт, очередь, метаданные и просмотр источников.
- `navigator/rag/` - индексация, поиск, ранжирование, генерация и проверка ответа.
- `navigator/schemas.py` - общие структуры данных и контракты компонентов.
- `navigator/main.py`, `navigator/templates/`, `navigator/static/` - веб-приложение и интерфейс.
- `services/ml/` - сервис embeddings и reranker.
- [Архитектура](docs/architecture.md), [контракты](docs/contracts.md), [проверка распознавания](docs/ocr-review.md), [безопасность](docs/security.md).
