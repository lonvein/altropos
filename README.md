# altropos

Локальный навигатор сотрудника по внутренним регламентам МФТИ: вопрос → гибридный
поиск → ответ с проверяемыми основаниями → переход к документу и дословной цитате.
Модели работают локально; документы и база не покидают контур организации.

> **Статус на 2026-11-12.** В репозитории есть UI, `/health`, Compose из трёх
> сервисов, профили, скрипты запуска/остановки/backup и CI. Проверены тесты,
> синтаксис Compose и локальный запуск приложения без Docker. Сборка образов,
> работа моделей, веса и GPU в этом окружении **не проверены**. Подробно —
> [docs/deployment.md](docs/deployment.md) и
> [docs/verification.md](docs/verification.md).

## Требования

### Общие

- Linux x86_64, Docker Engine 24+ и Docker Compose v2 (в проверке был CLI 5.6).
- Python 3.11–3.13 для штатной проверки тестов с закреплёнными зависимостями.
  Локальный прогон на Python 3.14 с более новыми пакетами дал 143 passed, но это
  не штатная сборка; CI использует Python 3.12 и пины из `requirements-*.txt`.
- 32 ГБ RAM и 40 ГБ свободного диска — ориентир, не измеренная гарантия.
- `git`, `curl`; для OCR — Tesseract с языками `rus+eng`, для PDF — `poppler-utils`.
  В образ приложения они уже установлены; на хосте нужны только для ручного запуска.

### Оборудование

| Сценарий | GPU | VRAM | Комментарий |
|---|---|---:|---|
| A100 | NVIDIA A100 | 40 ГБ+ | основной профиль, 14B Q4_K_M |
| 3060 Ti | RTX 3060 Ti | 8 ГБ | резерв, 8B Q4_K_M; поместится ли — не проверено |
| 4B fallback | та же 3060 Ti | 8 ГБ | ручной переход, без автоподмены |
| Разработка | без GPU | — | только контракты, BM25 и UI на fixtures |

Точные версии драйвера, `llama.cpp` и ревизии весов фиксируются совместно с Климом.
Скорость и качество без фактического замера не обещаются.

## Установка

### Что можно проверить сейчас

```bash
git clone https://github.com/lonvein/altropos.git
cd altropos
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Ожидаемо: все тесты проходят, модели и GPU не требуются. На 2026-11-12 локальный
прогон дал **143 passed** на Python 3.14 с более новыми зависимостями; штатная
проверка — CI на Python 3.12. Модели при этом не загружаются.

### Запуск приложения без моделей

```bash
. .venv/bin/activate
PROFILE=development LLM_ENABLED=false ML_ENABLED=false DATA_DIR=runtime \
  python -m uvicorn navigator.main:app --host 127.0.0.1 --port 8000
```

`/`, `/documents` и `/health` должны отвечать 200. В профиле `development` UI может
показывать явно помеченные синтетические данные. Это не ответ модели.

### Docker-контур

Файлы развёртывания находятся в корне: `docker-compose.yml`,
`compose.a100.yml`, `compose.3060ti.yml`, `Dockerfile`, `Dockerfile.ml`.
Профили — `config/profiles/*.env`, ревизии и SHA-256 — `config/models.lock.json`.
Полная инструкция: [docs/deployment.md](docs/deployment.md).

```bash
cp .env.example .env
./scripts/doctor.sh 4b
./scripts/download-models.sh 4b
./scripts/start.sh 4b --with-models
curl -fsS http://127.0.0.1:8000/health
```

Приложение слушает только `127.0.0.1`. Модельные сервисы не публикуют порты и
доступны приложению по внутренним адресам Compose (`embeddings-reranker:8081`,
`llm:8080`). Сборка и запуск контейнеров в текущем окружении не проверены:
Docker daemon недоступен. См. [docs/verification.md](docs/verification.md).

## Веса моделей

| Роль | Модель | Профиль | Ревизия |
|---|---|---|---|
| LLM | `Qwen/Qwen2.5-14B-Instruct-GGUF` Q4_K_M | A100 | `b466e1f8c07172155743e8e1307507d8a4f91fbd` |
| LLM | `Qwen/Qwen3-8B-GGUF` Q4_K_M | 3060 Ti | `7c41481f57cb95916b40956ab2f0b139b296d974` |
| LLM | `Qwen/Qwen3-4B-GGUF` Q4_K_M | 4B / резерв | `bc640142c66e1fdd12af0bd68f40445458f3869b` |
| Embeddings | `BAAI/bge-m3`, 1024, normalized | A100 GPU, остальные CPU | `5617a9f61b028005a4858fdac845db406aefb181` |
| Reranker | `BAAI/bge-reranker-v2-m3` | A100 GPU, остальные CPU | `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e` |

Точные файлы, размеры и SHA-256 закреплены в
[`config/models.lock.json`](config/models.lock.json). Скачивать только явной
командой, в постоянный volume:

```bash
./scripts/download-models.sh 4b     # Qwen3-4B + BGE + reranker, ~7 GiB
./scripts/download-models.sh a100   # Qwen2.5-14B (3 шарда) + BGE, ~12-13 GiB
./scripts/download-models.sh all    # все LLM-профили и BGE, ~20 GiB
```

Скрипт проверяет ревизии и контрольные суммы. `HF_TOKEN`, если нужен, передаётся
только через окружение на время скачивания: в `.env` и Git он не попадает.

- Веса не коммитить и не запекать в образ приложения; монтировать read-only.
- Проверять fingerprint `<model>@<revision>:1024:normalized`; при несовпадении
  векторный поиск запрещён, допустим явный BM25-режим.
- Qwen3 запускать без thinking mode; одновременно — один запрос к LLM.

## Профили

| Параметр | A100 | 3060 Ti | 4B |
|---|---:|---:|---:|
| LLM | Qwen2.5-14B Q4_K_M | Qwen3-8B Q4_K_M | Qwen3-4B Q4_K_M |
| Контекст | 16384 | 4096 | 4096 |
| Бюджет материалов | 8000 | 2200 | 2200 |
| Максимум ответа | 1536 | 768 | 768 |
| Фрагментов | 8 | 4 | 4 |
| Embeddings/reranker | GPU | CPU | CPU |

Профиль хранится в `config/profiles/<name>.env`: `a100`, `3060ti`, `4b`,
`development`. `scripts/start.sh <profile>` подключает нужный файл и GPU-override;
код приложения не меняется. Явные переменные окружения переопределяют профиль.
Переключение между машинами и профилями — только вручную. При нехватке контекста
система обязана сообщить об ограничении, а не обрезать инструкцию молча.

Qwen3 запускается без thinking mode (`--reasoning-budget 0`), одновременно
выполняется один запрос к LLM (`--parallel 1`).

## Запуск и остановка

```bash
./scripts/doctor.sh 4b            # Docker, диск, RAM, GPU
./scripts/download-models.sh 4b   # один раз; веса в volume
./scripts/start.sh 4b --with-models
curl -fsS http://127.0.0.1:8000/health
./scripts/smoke.sh                # реальные /embed, /rerank, /v1/chat/completions
```

`start.sh` собирает образ, поднимает приложение и, если веса найдены, модельные
сервисы. Без весов приложение стартует в ограниченном режиме, а `--with-models`
делает их отсутствие ошибкой.

Остановка:

```bash
./scripts/stop.sh                 # volume сохраняются
./scripts/stop.sh --purge --yes   # удалить только runtime volume
```

Данные лежат в именованном volume `altropos_runtime`, веса — в `altropos_models`;
`stop.sh` и `docker compose down` их не удаляют. Чистый запуск и остановка в Docker
в этом окружении не проверены: daemon недоступен. Локальный запуск приложения без
Docker проверен, см. [docs/verification.md](docs/verification.md).

## SSH-туннель

Веб-приложение на A100 слушает localhost. С рабочего места:

```bash
./scripts/tunnel.sh <user>@<a100-host>
# то же вручную: ssh -N -L 8000:127.0.0.1:8000 <user>@<a100-host>
```

Открыть `http://127.0.0.1:8000`. Не публиковать порт `8000` и модельные порты
в интернет, не отключать проверку ключа хоста. Для 3060 Ti — тот же приём с её адресом.

## Загрузка документов

Целевые точки API (реализует Егор, подключает Глеб):

| Endpoint | Назначение |
|---|---|
| `POST /api/documents` | multipart PDF/DOCX/XLSX → `document_id`, `job_id`, `status` |
| `POST /api/import-url` | `{url, selected_urls}` → `job_id`; только `mipt.ru` и поддомены |
| `GET /api/jobs/{id}` | состояние, ошибка, результат |
| `GET /api/documents` | список с метаданными и предупреждениями |
| `PATCH /api/documents/{id}/metadata` | название, номер, даты, подтверждение связей |
| `GET /api/sources/{fragment_id}` | HTML-представление источника с выделением |
| `GET /api/documents/{id}/original` | оригинал; PDF можно открыть с `#page=N` |

```bash
curl -fsS -F 'file=@document.pdf' http://127.0.0.1:8000/api/documents
curl -fsS http://127.0.0.1:8000/api/jobs/<job_id>
```

Состояния: `queued`, `processing`, `ready`, `needs_review`, `error`. В поиск
попадают только `ready` после согласованной публикации фрагментов и индекса.
`needs_review` исключён. Повторная загрузка того же SHA-256 возвращает существующий
документ. Импорт сайта не обходит весь сайт и не подтверждает связи автоматически.

## Перенос базы

```bash
./scripts/backup.sh --label before-update
# backups/altropos-runtime-<UTC>-before-update.tar.gz + .sha256 + .json

./scripts/restore.sh backups/altropos-runtime-...tar.gz --yes
```

`backup.sh` останавливает только `app`, делает `wal_checkpoint(TRUNCATE)`,
архивирует **всю** `DATA_DIR` одним снимком (SQLite, `originals/`, `extracted/`,
`indexes/`), проверяет архив и пишет SHA-256. `restore.sh` проверяет контрольную
сумму, при необходимости сначала снимает текущее состояние, распаковывает архив и
выполняет `PRAGMA integrity_check`.

Не копировать живую SQLite-базу и не смешивать файлы разных снимков. Старые
публикации не перезаписываются; новая версия документа получает новые ID.
Проверка backup/restore в Docker здесь не выполнялась — daemon недоступен.

## Ограничения

- Реальные регламенты МФТИ в Git не добавлены; качество на них не измерено.
  UI и тесты работают на синтетическом корпусе.
- Нет фактических прогонов на A100 и 3060 Ti. Таблица результатов заполнена
  как `не выполнялось`; заглушки вместо модели не использовались.
- Docker-стек, образы, healthcheck моделей, volume и backup/restore не проверены:
  Docker daemon в окружении разработки недоступен. См.
  [docs/verification.md](docs/verification.md).
- Реальные `/embed`, `/rerank` и `/v1/chat/completions` не вызывались: нет весов,
  `torch` и `llama-server`.
- 3060 Ti с 8 ГБ и Qwen3-8B не проверена; при нехватке памяти нужен ручной
  переход на 4B, а не автоматический.
- 40 вопросов относятся к искусственному корпусу. Перед защитой их нужно
  перепривязать к согласованным реальным документам и повторить разметку.
- Смысловая проверка той же моделью не является независимым доказательством.
- Штатная версия Python — 3.11–3.13; локальный прогон на 3.14 не заменяет CI.
- Видео не записано, рассказ защиты не утверждён Климом.

## Безопасность

- `.env`, веса, базы, индексы, оригиналы документов и персональные данные не
  коммитятся; `.gitignore` это закрывает.
- В репозитории нет секретов и внутренних файлов; проверка от 2026-11-12
  не нашла `.env`, ключей и двоичных документов. Повторить: `./scripts/check_hygiene.sh`.
  Подробнее — [docs/security.md](docs/security.md).
- Выводимый текст экранируется; ответ модели не вставляется через небезопасный
  `innerHTML`.
- Документы считаются данными: команды внутри них не меняют правила системы.
- Перед демонстрацией убрать токены, URL с доступами, имена файлов и данные
  из экрана; видео и слайды проверить на секреты.
