# Распознавание и одобрение стартового корпуса

Стартовые документы и документы для ручной проверки загрузки разделены локальным
manifest. Реальные файлы, имена, результаты OCR и решения хранятся под `runtime/`
и не попадают в Git. Подготовка пакетов не вызывает модели, GPU, Store и Indexer.

## OCR

На Windows `./scripts/setup_ocr.ps1` извлекает переносимый Tesseract в `runtime/ocr-tools/`.
Исполняемый файл и русский языковой пакет проверяются по закреплённым SHA-256.
Установка не меняет PATH/реестр. Укажите напечатанные `TESSERACT_CMD` и
`TESSDATA_PREFIX` в локальном `.env`. Требуются языки `rus`, `eng` и `osd`.
На других системах используется локальный Tesseract с теми же языками.

PDF обрабатывается постранично: пригодный текстовый слой сохраняется, для сканов
вызывается OCR. Проверяются ориентации 0/90/180/270 и небольшой наклон; сомнительная
ориентация и низкая уверенность сохраняют `needs_review`. Координаты возвращаются
к системе оригинала. `/api/health` отдельно сообщает доступность OCR и моделей.

Пропуски, нули и филлеры таблиц различаются. Значения не восстанавливаются по
догадке; формулы без сохранённого результата не вычисляются. OCR сканированных
таблиц сохраняет текст и координаты, но не гарантирует восстановление сетки.
Сноски должны сохраняться вместе с основаниями; неуверенные связи требуют проверки.

## Подготовка

Команды выполняются из корня репозитория с Python и зависимостями проекта.
Имена ниже искусственные; нужное число `--manual` задаёт отложенную группу.

```powershell
python -B scripts/prepare_corpus.py --env-file .env split C:/local/sources runtime/corpus-review/corpus-manifest.json --manual test.pdf --manual test.xlsx
python -B scripts/prepare_corpus.py --env-file .env prepare runtime/corpus-review/corpus-manifest.json runtime/corpus-review
```

Для отдельного пилота из отложенной группы добавьте `--pilot test.pdf` к `prepare`.
Группа пилота останется `manual_test`: даже одобрение не добавит его в стартовую базу.
Укажите абсолютный `CORPUS_MANIFEST` в `.env` приложения, чтобы обычная загрузка
стартового SHA-256 не обходила этот процесс. При недоступном manifest загрузка
блокируется до устранения ошибки. Отложенные файлы загружаются обычным API.

## Проверка человеком

Откройте `/review` локально. Каждый пакет содержит копию оригинала, PNG страниц
PDF, текст, таблицы, сноски, итоговые фрагменты и диагностику. Это просмотр без
кнопки автоматического одобрения. Проверяющий агент показывает документы
небольшими группами и ждёт явного решения пользователя по каждому.

Решение записывают только после такого ответа:

```powershell
python -B scripts/corpus_review.py --env-file .env decision runtime/corpus-review/PACKAGE --decision approved --reviewer HUMAN --comment "Явное решение пользователя"
```

Вместо `approved` доступны `rejected` и `excluded`. Технический `needs_review`,
отсутствие фрагментов и ошибки просмотра блокируют одобрение. Нужно исправить
распознавание и заново показать пакет. Одобрение OCR не устанавливает юридическое
`metadata.reviewed` и не подтверждает действие приказа или его связи.

Контрольные суммы связывают решение с оригиналом, результатом извлечения,
фрагментами, страницами и версией парсера/OCR. Изменение любого из них требует
нового пакета и нового решения. Для всех CLI используйте один `.env` и пути OCR.
Это локальный журнал доверенного оператора, а не криптографическая подпись человека.

## Публикация после решений

```powershell
python -B scripts/prepare_corpus.py --env-file .env publish runtime/corpus-review/corpus-manifest.json runtime/corpus-review
# Только после успешной предварительной проверки и решения пользователя:
python -B scripts/prepare_corpus.py --env-file .env publish runtime/corpus-review/corpus-manifest.json runtime/corpus-review --apply
```

Без `--apply` нет записи в базу и вызовов моделей. Нерешённый стартовый документ
блокирует весь пакет до любых изменений базы. Явно исключённые и отклонённые
документы пропускаются. Индексатор получает именно одобренные фрагменты, повторно
OCR при публикации не запускается. Отложенная группа не публикуется этой командой.
Для исходника с иной уже зарегистрированной версией требуется отдельная миграция.

В интерфейсе документов повторная обработка доступна для `failed`/`needs_review`.
Она использует неизменённые исходные байты и текущую конфигурацию OCR, но не
подменяет решение человека и не меняет `metadata.reviewed`.
