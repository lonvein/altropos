# Два обязательных use case

Оба сценария используют только искусственные документы. Ожидаемые ответы — не
заглушки: на стенде они должны быть получены через настоящий `/api/ask` с моделью
и источниками. Текущий статус: **не выполнялось**. Веб-оболочка и загрузка
проверены на синтетической заглушке, но реальные RAG/ingestion routers, веса и
стенд отсутствуют; проверка оболочки не считается выполнением use case.

## UC-1

### Обычный вопрос → несколько источников

**Цель.** Показать, что ответ опирается на действующую редакцию, содержит два
разных факта из двух пунктов и каждое утверждение открывается в источнике.

**Предусловия.**
- Профиль A100 (`a100`), модели загружены, ML доступен.
- В `DATA_DIR` опубликованы документы искусственного корпуса, включая
  «Изменение № 1 к Порядку организации учебных мероприятий».
- Дата запроса — `2026-03-15`: изменение уже действует, памятки от 2026-04-01 ещё нет.

**Вопрос.**

> Мероприятие на 35 участников назначено на 20 мая 2026 года. За сколько дней
> подать заявку и нужно ли подтверждение декана?

**Ожидаемый результат.**
- `status = answered`, `answer_mode = generated`, `verification.supported = true`,
  `verification.complete = true`, `verification.conflict = false`.
- В ответе два существенных факта:
  1. заявка — не позднее чем за **15 рабочих дней**;
  2. подтверждение декана нужно, потому что участников **более 30**.
- `sources` содержит два фрагмента из `syn-org-amend-v1` (§1 и §2); URL имеют вид
  `/api/sources/<fragment_id>` и ведут именно к этим фрагментам.
- Цитаты дословно совпадают с текстом фрагментов.
- Нет утверждений «10 рабочих дней» и «более 50»: это старая редакция.

**Проверка вручную.**
1. Отправить вопрос, дождаться ответа.
2. Открыть каждую ссылку; убедиться в странице/абзаце и выделении.
3. Обновить страницу источника (F5), открыть в новой вкладке.
4. Вернуться назад: вопрос и ответ сохранились, повторной отправки нет.

**Критерий приёмки.** Оба факта, обе цитаты и обе ссылки корректны; статус и
verification соответствуют ожиданию. Время ответа записано фактически, без обещаний.

## UC-2

### Нехватка данных → загрузка документа → подтверждение

**Цель.** Показать честный отказ, затем добавление нового документа без правки
кода и появление проверяемого ответа.

**Предусловия.**
- В корпусе нет документа о парковке.
- Подготовлен искусственный файл `demo-parking.docx` (создать на стенде, в Git
  не добавлять). Содержимое:

  > ИСКУССТВЕННЫЙ ПРИМЕР. Правила парковки. Стоимость парковки для сотрудников
  > составляет 100 условных единиц в месяц.

**Шаг 1. Вопрос без источника.**

> Сколько стоит парковка для сотрудников на территории кампуса?

Ожидаемо: `status = not_found`, `summary` и `steps` пусты, утверждений и
придуманных ссылок нет; есть объяснение, что подходящего документа нет.
Если LLM отключена — `sources_only`/ограниченный режим с предупреждением,
но не выдуманная цена.

**Шаг 2. Загрузка.**

1. Открыть «Документы», загрузить `demo-parking.docx`.
2. Убедиться, что состояние меняется `queued → processing → ready`.
3. Пока документ не `ready`, поиск его не видит; `needs_review` тоже не видит.
4. Повторно загрузить тот же файл: возвращается существующий `document_id`,
   второго задания и дубликата нет.

**Шаг 3. Повторный вопрос.**

> Сколько стоит парковка для сотрудников на территории кампуса?

Ожидаемо:
- `status = answered`, ответ «100 условных единиц в месяц»;
- ровно один подтверждающий источник, цитата дословная;
- ссылка открывает загруженный документ и нужный блок;
- ответ не содержит других тарифов и условий.

**Шаг 4. Перезапуск.**

Перезапустить приложение, повторить вопрос и открыть источник. Документ,
метаданные и цитата сохраняются. Затем остановить приложение, перенести `DATA_DIR`
по README и повторить — результат тот же.

**Критерий приёмки.** До загрузки — корректный `not_found`; после `ready` —
корректный `answered` с одним источником; дубликата нет; после перезапуска и
переноса всё работает. Если документ не опубликован, ответ остаётся `not_found`,
а не подменяется содержимым файла в обход индекса.
