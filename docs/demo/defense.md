# Слайды и сценарий защиты

Статус: **черновик**. Утверждает Клим как капитан; до утверждения рассказ не
считается финальным. Фактические результаты не выдумывать: на слайде 9 стоит
«не выполнялось», пока нет прогонов на A100 и 3060 Ti.

Формат: 10 слайдов, 6–7 минут, затем вопросы. Один слайд — одна мысль.
Скриншоты и видео вставлять только после реального прогона.

## Слайд 1. Титул

**На экране:** «altropos. Локальный навигатор по регламентам». Имена команды,
дата, одна строка: «Ответ с источником, а не ответ по памяти».

**Реплика.** «Мы сделали прототип, который отвечает на вопросы по внутренним
регламентам и показывает, откуда взято каждое утверждение. Всё считается локально».

## Слайд 2. Задача

**На экране:** три боли — долгий поиск, устаревшие редакции, недоверие к ответу
бота. Пользователи: сотрудник и администратор документов.

**Реплика.** «Сотруднику нужно не просто найти файл, а понять порядок действий и
убедиться, что он смотрит действующую редакцию. Администратору нужно добавлять
документы без программиста».

## Слайд 3. Что делает прототип

**На экране:** цепочка «вопрос → поиск → проверенный ответ → цитата → документ».
Статусы: answered / partial / not_found / ambiguous / conflict / unavailable.

**Реплика.** «Система либо даёт ответ с цитатами, либо честно говорит, что данных
не хватает, нужен уточняющий вопрос или есть противоречие. Частичный ответ не
называется полной инструкцией».

## Слайд 4. Архитектура

**На экране:**

```text
Егор: файлы / mipt.ru → очередь → извлечение → Fragment[]
Клим: BM25 + FAISS → RRF → reranker → LLM → проверка → AskResponse
Глеб: FastAPI + Jinja2 → вопрос, документы, источники, /health
```

**Реплика.** «Один FastAPI-процесс, SQLite и файлы в DATA_DIR. Модели — отдельные
локальные сервисы. Поиск видит только опубликованные ready-документы; needs_review
исключён. Переключение A100 / 3060 Ti — только вручную».

## Слайд 5. Документы и редакции

**На экране:** PDF/DOCX/XLSX/HTML, OCR, locator, SHA-256, версии, связи
`amends/repeals/appendix`, `as_of`.

**Реплика.** «Егор отвечает за извлечение и происхождение. Новое содержимое — новая
версия и новые ID. Поправка не заменяет старый документ молча. Дата запроса
фильтрует подтверждённые периоды действия; неизвестная актуальность — предупреждение».

## Слайд 6. Почему ответу можно верить

**На экране:** три барьера: структурная проверка JSON и ID → дословная цитата →
смысловая проверка и один retry. При сбое — только extracts/sources_only.

**Реплика.** «Модель не придумывает название и URL: их добавляет сервер по базе.
Каждая цитата — точная подстрока фрагмента. Если проверка не прошла, мы не
публикуем вывод как окончательный. Смысловая проверка той же моделью — не
независимое доказательство, это ограничение мы признаём».

## Слайд 7. Интерфейс и развёртывание

**На экране:** две страницы, состояния загрузки, `/health`, Docker Compose,
SSH-туннель, профили A100 / 3060 Ti / 4B.

**Реплика.** «Сотрудник задаёт вопрос и открывает источник; администратор
загружает файл и видит очередь. Приложение слушает localhost, доступ — через
SSH-туннель. Модельные сервисы не опубликованы в интернет. Веса монтируются
отдельно и не попадают в Git».

## Слайд 8. Как проверяли

**На экране:** 40 вопросов; 28 Глеба + 12 Егора; 20/20; категории; Recall@8 /
Recall@4; точные цитаты; запрет заглушек.

**Реплика.** «Мы заранее разделили набор на настройку и финал, сохранив категории:
одиночные, составные, без ответа, конфликты, OCR, таблицы, редакции. Финал
замораживается и прогоняется один раз на каждой машине. Заглушки вместо модели
запрещены».

## Слайд 9. Результаты

**На экране:** таблица из `docs/results.md`: контракты — 117 passed; A100 — не
выполнялось; 3060 Ti — не выполнялось; UI — не выполнялось; причина.

**Реплика.** «Здесь важна честность. Контракты и разметка проверены, 117 тестов
проходят. Фактических прогонов на A100 и 3060 Ti не было: нет доступа к стенду,
весам и интегрированному приложению. Мы не подставляем fixtures и не пишем
выдуманные проценты. Поэтому цель Recall ≥ 90 % пока не подтверждена».

## Слайд 10. Ограничения и следующий шаг

**На экране:** три пункта — реальные документы, два стенда, видео/утверждение.
Плюс риски: 8 ГБ на 3060 Ti, конфликты редакций, смысловая проверка той же моделью.

**Реплика.** «До защиты нужно перепривязать 40 вопросов к согласованным реальным
документам, прогнать обе машины и записать видео. Если 8B не помещается в 8 ГБ,
вручную переходим на 4B. Рассказ и цифры утверждает Клим».

## Вопросы и ответы

**Почему нет результатов на реальных документах?**
Внутренние документы не переданы в рабочее дерево и не могут попадать в Git без
разрешения. Набор проверен на явно синтетическом корпусе; это проверяет механику,
но не качество на регламентах МФТИ. Это записано как ограничение.

**Почему не 700 документов?**
Такое число не испытывалось. Мы не заявляем масштаб, который не проверяли.

**Откуда уверенность, что модель не придумает ответ?**
Структурная проверка, точные цитаты, смысловая проверка, ограниченные режимы.
При сбое публикуются только проверенные выдержки или источники без выводов.

**Что при противоречии документов?**
Статус `conflict`, показываются оба основания и предупреждение; окончательный
итог не объявляется. Более поздняя дата сама по себе не отменяет документ.

**Что если модель или GPU недоступны?**
Поиск и источники остаются, BM25 с явным предупреждением; без LLM — `sources_only`.
Автоматического переключения на другую машину нет.

**Почему 3060 Ti с 8 ГБ?**
Это резервный профиль с 8B Q4_K_M и 4B fallback. Поместится ли 8B — не обещаем
до фактической проверки памяти.

**Где видео?**
Сценарий готов, запись не выполнена без работающего стенда. Подставлять
записанный заранее JSON вместо живого ответа мы не будем.
