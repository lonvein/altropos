# Цикл RAG: состояние на 13 ноября 2026

Реализован текущий этап: `POST /api/ask` связывает ready-поиск, ограничение контекста,
генерацию Draft, проверку точных цитат и отдельный вызов смысловой проверки.
Допускается одно исправление. После повторного отказа возвращаются источники без
неподтверждённых выводов. Названия и URL берутся сервером из хранилища.

Подключены реальные загрузка, очередь одного worker, метаданные, оригинал и
`/api/sources/{fragment_id}`. Источник показывает экранированный опубликованный текст
и locator. Это минимальное представление фрагмента, не полный просмотрщик страницы.
Редактирование метаданных сохраняет ready; review ставит повторную обработку,
но не обходит проверку читаемости. Оригинал неизменяем: изменённые байты требуют новой загрузки.

## Запуск

Установить `requirements-dev.txt` в отдельное Python 3.11+ окружение (для приложения
достаточно `requirements.txt`). Настроить `.env`: `DATA_DIR`, профиль, точные ревизии,
`LLM_ENABLED`, `ML_ENABLED` и адреса доступных модельных сервисов.
Включение моделей с пустой/UNVERIFIED ревизией запрещено.

Для существующего SSH-туннеля на хосте:

```dotenv
PROFILE=3060ti
ML_URL=http://127.0.0.1:8081
LLM_URL=http://127.0.0.1:8082/v1
UI_SYNTHETIC_FALLBACK=false
```

```shell
python -m uvicorn navigator.main:app --host 127.0.0.1 --port 8000
```

По умолчанию API реальные. Без моделей можно загружать документы, искать BM25 и
открывать источники; claims при отключённой LLM не создаются. Для отдельной оболочки
на fixtures нужно явно включить `UI_SYNTHETIC_FALLBACK=true`; она помечена как демо.
В контейнере loopback относится к контейнеру: адреса SSH-туннеля требуют отдельной настройки.

`request_timeout` ограничивает отдельную операцию; общий HTTP deadline вопроса —
`4 × request_timeout`, включая поиск и ожидание блокировки. UI ждёт этот предел
плюс 30 секунд. После отмены HTTP активный поток не считается остановленным:
следующая операция получает busy, пока он не завершится. Индексатор и поиск имеют
раздельные embeddings-клиенты, поскольку используют разные потоки/event loops.

## Проверка на настоящих моделях

```shell
python scripts/check_rag_cycle.py path/to/client.env
```

Скрипт создаёт временную базу и искусственный DOCX, проходит загрузку, hybrid
публикацию, вопрос, проверку цитат и открытие источника/оригинала. Рабочий корпус не
читается, веса не скачиваются. Отчёт пишется в игнорируемый `runtime/api-cycle-live.json`.

На доступном SSH-стенде выполнен один такой сценарий:

| Параметр | Наблюдение |
|---|---|
| LLM | Qwen3-8B Q4_K_M, контекст 4096, без thinking |
| llama.cpp | b12321 / 09338b85e8b230742fa56f93a1d9f0bf006ca2d3 |
| Embeddings / reranker | BGE-M3 / BGE reranker v2 m3, CPU |
| Индексирование DOCX | ready, hybrid, 2,39 с |
| Вопрос | HTTP 200, answered/generated, 6,22 с |
| Проверка | supported=true, complete=true, conflict=false |
| Источники | HTTP 200, дословные цитаты совпадают; оригинал доступен |

Это единичная техническая проба, не средняя скорость и не метрика качества.
Порог reranker не откалиброван; предупреждение остаётся в ответе. Конкретные Docker
образы из lock-файла этим SSH-прогоном не проверены. A100 и профиль 4B не проверялись.

Первый искусственный запрос с неточной цитатой был безопасно отклонён. По результату
исправлен стык клиента и pipeline: структурно валидный отклонённый Draft сохраняется
только внутри исключения для repair и не попадает в публичную ошибку.

## Границы этапа

Не закрыты: качество на комплекте регламентов, 20/20 вопросов, калибровка, автоматические
подзапросы и связанные условия/поправки, сетевой импорт mipt.ru, полный просмотрщик
оригинала и чистый Docker-прогон. Известные ограничения парсеров из аудита (в частности,
ограничение XLSX 20000 строк и приблизительный размер фрагментов) не устранены этим этапом.
Следующий шаг — ограниченный прогон реальных документов и контрольных вопросов с
ручной проверкой полноты, без добавления новых крупных функций.
