# Подсистема документов, парсинга, редакций и источников

Документ описывает модуль `navigator/ingestion/` и `navigator/documents/` для интеграции, сборки контейнеров, эксплуатации и защиты.

## 1. Поддерживаемые форматы и адресация (`locator`)

| Формат | Модуль | Способ разбора | Формат `locator` | Особенности |
|---|---|---|---|---|
| **PDF** | `navigator/ingestion/pdf_parser.py` | `pdfplumber` + автоматический OCR (`pypdfium2` + `pytesseract`) на страницах без текста | `{"kind": "pdf", "page": N, "bbox": [x0, y0, x1, y1]}` | Нумерация страниц с 1; фрагменты не пересекают границы страницы; таблицы выделяются отдельно и делятся с повторением шапки |
| **DOCX** | `navigator/ingestion/docx_parser.py` | `python-docx` | `{"kind": "docx", "block": idx}` | Сохраняется порядок абзацев и таблиц, иерархия пунктов и заголовков; таблицы нарезаются группами строк с повторением шапки |
| **XLSX** | `navigator/ingestion/xlsx_parser.py` | `openpyxl` (`data_only=True` + чтение формул) | `{"kind": "xlsx", "sheet": "...", "range": "A1:C10"}` | Формулы **не пересчитываются**; при отсутствии кэшированного результата явно указывается формула и пометка «значение не сохранено» (ноль не подставляется) |
| **HTML** | `navigator/ingestion/html_parser.py` | `BeautifulSoup` (`lxml`) | `{"kind": "html", "block": idx}` | Удаляются `<nav>`, `<header>`, `<footer>`, `<script>`, `<style>`; сохраняются таблицы, заголовки и ссылки на документы |

Целевой размер фрагмента: ориентир **500 токенов** (предел ~800 с запасом под заголовки и контекст), перекрытие для длинных текстовых блоков — **80 токенов**, короткие списки и вводные строки с двоеточием не разрываются.

## 2. Настройка OCR (Tesseract)

Для распознавания отсканированных PDF используются системный бинарник `tesseract`, обёртка `pytesseract` и рендер страниц `pypdfium2` (300 DPI, языки `rus+eng`):

- Linux / Docker:
  - Пакеты: `tesseract-ocr`, `tesseract-ocr-rus`, `tesseract-ocr-eng`.
- Windows:
  - Установленный `Tesseract-OCR` (`C:\Program Files\Tesseract-OCR\tesseract.exe` или переменная окружения `TESSERACT_CMD`).
  - Каталог `tessdata` (`rus.traineddata`, `eng.traineddata`): рекомендуется задать `TESSDATA_PREFIX` с **ASCII-путём** (например, `runtime/tessdata`), чтобы избежать ошибок кодировки пути в `pytesseract` на Windows.
- При нечитаемом скане или недоступном OCR документ **не отбрасывается молча**: выставляется `needs_review=True`, предупреждение с перечислением нераспознанных страниц, и документ не публикуется в поисковый индекс до ручной проверки.

## 3. Загрузка, хранение и очередь (`navigator/documents/`)

- **Хранение (`storage.py`)**:
  - Загружаемые файлы проходят проверку расширения (`.pdf`, `.docx`, `.xlsx`, `.html`, `.htm`) и лимита `MAX_UPLOAD_MB` (по умолчанию 40 МБ).
  - Пользовательское имя не используется в пути ФС: оригинал сохраняется в `runtime/originals/<id>.<ext>`, промежуточные блоки — в `runtime/extracted/<id>.blocks.json`.
  - Валидация путей (`_safe_path`) предотвращает выход за пределы `DATA_DIR`.
- **Дедупликация**: по SHA-256 содержимого; повторная загрузка возвращает существующий `document_id` и актуальное состояние без создания дублей.
- **Персистентная очередь (`queue.py`)**:
  - Задачи хранятся в SQLite-таблице `jobs` (`queued` → `processing` → `ready` / `needs_review` / `failed`).
  - Файловая блокировка (`document-worker.lock`) гарантирует выполнение строго одной задачи индексации/импорта одновременно.
  - `recover_stale_jobs()` возвращает незавершённые при рестарте задачи обратно в `queued`.
  - Сбой разбора одного документа изолируется в статусе `failed` и не останавливает очередь.
- **Публикация (`service.py`)**: документ получает статус `ready` и попадает в выдачу только после успешного вызова `Indexer.index_document(doc_id, fragments)` (BM25 либо Hybrid при включённом ML-сервисе).

## 4. Безопасный просмотрщик источников и ограниченный импорт с `mipt.ru`

- **`GET /api/sources/{fragment_id}` (`viewer.py`)**:
  - Читает только снимок активной публикации (`status='ready'`) из SQLite `publications`, никогда не отдаёт сырые непроверенные файлы как HTML.
  - Показывает все фрагменты документа в порядке `ordinal`, подсвечивает целевой фрагмент (`<mark>`), отображает человекочитаемый адрес и JSON `locator`, а при отсутствии дат в метаданных — предупреждение о неизвестной актуальности редакции.
  - Экранирует весь текст через `html.escape(..., quote=True)` и отдаётся с заголовками:
    - `Content-Security-Policy: default-src 'none'; style-src 'self' 'unsafe-inline'; frame-ancestors 'self'; sandbox`
    - `X-Content-Type-Options: nosniff`
- **`POST /api/import-url` (`site_importer.py`)**:
  - Разрешены **строго** схемы `http`/`https` и домен `mipt.ru` или `*.mipt.ru`.
  - Отклоняются похожие домены (`evil-mipt.ru`, `mipt.ru.evil.org`), IP-адреса, `localhost`, URL с `username:password@`, а также схемы `file://`, `ftp://`, `javascript:`.
  - Все HTTP-редиректы выполняются вручную с повторной проверкой каждого адреса назначения; размер ответа ограничивается `max_bytes`, таймаут — `request_timeout`.
  - Без `selected_urls` задача `import_preview` возвращает заголовок, выдержку и разделённые списки `links` (разрешённые PDF/DOCX/XLSX на `mipt.ru`) и `rejected` (внешние или неподдерживаемые). С `selected_urls` задача `import_url` скачивает выбранные файлы, сохраняет `source_url` и `retrieved_at` и ставит их в стандартный конвейер индексации.

## 5. Метаданные, связи и редакции (`metadata_extractor.py`, `service.py`)

- При парсинге из шапки документа автоматически извлекаются `number`, `issued`, `valid_from`, `valid_to` и предложения связей (`amends`, `repeals`, `appendix`, включая целевой `target_section`, если указан пункт/раздел).
- Все автоматически найденные связи создаются со статусом **`confirmed=False`** (предложение до проверки администратором) — более поздний приказ сам по себе не отменяет предыдущий.
- В `DocumentService` реализовано двустороннее разрешение `Relation.target_id` по номеру приказа (`metadata.number` ↔ `documents.id`), независимо от того, загружен ли базовый приказ раньше или позже изменяющего/отменяющего документа.
- При запросе `PATCH /api/documents/{id}/metadata` администратор подтверждает метаданные (`reviewed=True`), даты действия (`valid_from <= valid_to`) и связи (`confirmed=True`), которые затем учитываются поисковиком при фильтрации по дате `as_of`.
