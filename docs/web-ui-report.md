# Веб-интерфейс Altropos: что реализовано и что дальше

Дата: **2026-11-12**. Ветка: `feature/web-deploy`.
Отчёт фиксирует состояние после коммита `60849cf`; сам документ добавлен
отдельным коммитом.

Документ разделяет три вещи:

1. что уже реализовано и проверено;
2. что проверено только на явно обозначенных заглушках;
3. что предстоит сделать после появления реальных routers и доступа к стенду.

## 1. Реализовано

### 1.1. Страница «Задать вопрос»

Файлы: `navigator/templates/ask.html`, `navigator/static/js/ask.js`,
`navigator/static/css/app.css`.

- Поле вопроса и необязательная дата `as_of`.
- Ожидание ответа с тайм-аутом; повторная отправка только вручную.
- Сохранение введённого вопроса при пустом запросе, тайм-ауте, отказе модели
  и сетевой ошибке.
- Вывод ответа и нумерованных шагов.
- Отдельный вывод всех шести статусов:
  `answered`, `partial`, `not_found`, `ambiguous`, `conflict`, `unavailable`.
- Список источников с цитатами; открытие источника в отдельном диалоге.
- Текст ответа, цитаты и метаданные вставляются через `textContent`, без
  небезопасного `innerHTML`.
- Для HTML-представления источника используется sandboxed iframe.

### 1.2. Страница «Документы»

Файлы: `navigator/templates/documents.html`,
`navigator/static/js/documents.js`.

- Загрузка PDF/DOCX/XLSX.
- Список документов с метаданными и предупреждениями.
- Polling `GET /api/jobs/{id}` и пять статусов с русскими подписями:
  `queued`, `processing`, `ready`, `needs_review`, `error`.
- Импорт по URL с предварительным выбором найденных ссылок.
- Ручное подтверждение связей между документами; связи не подтверждаются
  автоматически.
- Просмотр оригинала и HTML-представления источника.
- Ограничение размера загрузки берётся из настроек приложения.

### 1.3. Интеграция с routers

Файлы: `navigator/main.py`, `navigator/ui/integration.py`.

- Подключение routers Клима и Егора без жёсткой привязки к одному имени модуля.
- Поиск модуля по переменным `ASK_ROUTER_MODULE` и `DOCUMENTS_ROUTER_MODULE`,
  затем по согласованным кандидатам.
- Ошибка импорта не скрывается: причина попадает в `/health` и в баннер UI.
- Реальные routers имеют приоритет над заглушкой.

### 1.4. `/health`

Файлы: `navigator/ui/health.py`, `navigator/templates/base.html`.

- Всегда отвечает HTTP 200; состояние передаётся в JSON.
- Статусы: `ok`, `limited`, `degraded`.
- Показывает состояние приложения, ML и LLM, режим данных и причины ограничений.
- Кэш на 5 секунд, чтобы опрос не создавал лишнюю нагрузку.
- Диалог состояния доступен из интерфейса.

### 1.5. Явно помеченный демонстрационный режим

Файл: `navigator/ui/synthetic.py`.

- Синтетические API включаются только при отсутствии реальных routers и только
  если это разрешено настройкой.
- По умолчанию разрешены только для `PROFILE=development`.
- Каждый ответ содержит предупреждение `ДЕМО-ЗАГЛУШКА`; страницы показывают
  баннер демонстрационного режима.
- В production-профиле без routers заглушки не монтируются: API отвечает 404,
  `/health` показывает `degraded`.
- Пустое значение `UI_SYNTHETIC_FALLBACK` трактуется как «не задано», чтобы
  Compose не отключал развитие по умолчанию.

### 1.6. Развёртывание и проверки

- `Dockerfile`, `Dockerfile.ml`, `docker-compose.yml`, профили в `config/`.
- CI: тесты, валидация Compose, сборка образа и проверка перезапуска.
- `GET /health` используется и приложением, и Docker healthcheck.
- Security-заголовки и CSP для страниц и HTML-источников.
- Тесты: `tests/test_ui.py`, `tests/test_health.py`, `tests/test_deployment.py`.

### 1.7. Исправленные ошибки

- `UI_SYNTHETIC_FALLBACK`, переданный пустой строкой из Compose, ошибочно
  отключал заглушки в `development`.
- CI-смоук искал `"profile": "development"` в компактном JSON, где пробела
  после двоеточия нет; проверка заменена на разбор JSON.
- `backup.sh` и `restore.sh` возвращают владельца файлов после операций,
  выполняемых от root.

## 2. Что проверено

### 2.1. Локально без Docker

```bash
.venv/bin/python -m pytest -q
# 146 passed, 1 warning
```

Проверены страницы, `/health`, шесть статусов ответа, пять статусов документов,
polling, импорт URL, метаданные, ссылки на источники и экранирование.

### 2.2. В Docker

Собрано `altropos-app:ci`. При `PROFILE=development` без моделей:

- `/health` → 200, `status: limited`, `data_mode: synthetic`;
- `/` и `/documents` открываются;
- `POST /api/ask` возвращает `answered` с источником;
- загрузка PDF доходит до `ready`, оригинал отдаётся;
- данные в volume сохраняются после `docker restart`.

### 2.3. Ограничения проверки

- Реальные routers `navigator.rag.*` и `navigator.documents.*` в дереве
  отсутствуют. Сквозной путь проверен на синтетическом backend.
- Реальные регламенты МФТИ не используются; качество ответов не измерено.
- A100 и 3060 Ti не запускались; влезание моделей в VRAM не подтверждено.
- GitHub Actions запускается на стороне GitHub; результат конкретного прогона
  нужно смотреть в интерфейсе репозитория.
- OCR и разбор реальных PDF/DOCX/XLSX зависят от парсеров Егора.

## 3. Что предстоит реализовать

| Задача | Условие готовности | Зависимость |
|---|---|---|
| Подключить реальный ask-router | `POST /api/ask` отвечает по контракту, `/health` показывает `mode: real`, баннер заглушки исчезает | Клим, `navigator/rag/` |

| Проверить импорт сайта | разрешены только `mipt.ru` и поддомены; связи не подтверждаются автоматически | Егор |
| Прогнать CI на GitHub | все три job зелёные на последнем коммите | доступ к Actions |
| Создать PR в `main` | изменения проверены, описание и ограничения указаны | Клим |
| Прогнать A100 / 3060 Ti | записаны VRAM, время загрузки и контрольный вопрос | стенд с GPU |

| Проверить backup/restore на volume | снимок восстановлен, `PRAGMA integrity_check` → `ok`, контрольный вопрос повторён | Docker-стенд |

## 4. Правила, которые нельзя нарушать при доработке

- Заглушка не должна выглядеть как реальный ответ: предупреждение и баннер
  обязательны.
- В production-профиле синтетические API не монтируются без явного разрешения.
- Поиск видит только опубликованные `ready`-документы; `needs_review` исключён.
- У каждого утверждения — дословная цитата; название и URL источника добавляет
  сервер.
- Команды из документов считаются данными, а не инструкциями системе.
- Отказ модели и тайм-аут обозначаются явно; автоматического повтора нет.
- Пользовательский текст и ответ модели не вставляются через `innerHTML`.
- Секреты, `.env`, базы, индексы, оригиналы документов и веса не коммитятся.

## 5. Быстрая проверка после слияния

```bash
.venv/bin/python -m pytest -q

docker build -t altropos-app:ci .
docker run -d --name altropos-check \
  -p 127.0.0.1:18001:8000 \
  -e PROFILE=development -e LLM_ENABLED=false -e ML_ENABLED=false \
  -e UI_SYNTHETIC_FALLBACK=true altropos-app:ci
curl -fsS http://127.0.0.1:18001/health
docker rm -f altropos-check
```

Если текущая сессия не видит новую группу `docker`, обернуть команды:
`newgrp docker -c '<команда>'`.

После подключения реальных routers те же команды должны показать
`data_mode: real` и отсутствие предупреждений о заглушке.
