# Проверка репозитория по ТЗ

Пакет содержит требования, готовый промпт для независимого аудита и план следующих изменений. Он подготовлен 13 ноября 2026. Это задание для проверки, а не готовый отчёт о полном соответствии ТЗ.

| Файл | Назначение |
|---|---|
| [requirements.md](requirements.md) | Все требования исходного ТЗ, 100 технических и 30 отраслевых баллов, входной набор и отдельно дополнения пользователя |
| [repository-audit-prompt.md](repository-audit-prompt.md) | Промпт для нового проверяющего агента: порядок работы, доказательства, статусы и формат результатов |
| [next-steps.md](next-steps.md) | Подробная последовательность реализации: интеграция Егора, пять ручных файлов, качество RAG, эксплуатация, сдача |

## Как использовать

1. Открыть репозиторий на нужной ветке и зафиксировать `git rev-parse HEAD` и `git status --short --branch`.
2. Передать новому агенту весь [промпт](repository-audit-prompt.md) и поручить аудит этого SHA. Агент читает [реестр](requirements.md), а планы использует для ориентации, не как доказательство готовности.
3. Получить отчёт, полную матрицу требований, находки и следующий ограниченный этап. Сначала проверить пробелы матрицы и доказательства, затем поручать исправления.

При отсутствии оригинального DOCX аудитор использует извлечённый реестр, но прямо отмечает невозможность независимо сверить полноту исходного ТЗ. Содержимое организационных файлов, приватные результаты и секреты в публичные отчёты не копируются.

## Границы текущего пакета

В интеграцию включены подготовленные изменения PR #9–#11: OCR/review, исправления таблиц и символов, PDF bbox и серверный контур. Новый PR [#12 Егора](https://github.com/lonvein/altropos/pull/12) с viewer/importer описан первым следующим этапом: его отдельные проверки не заменяют совместимость с этим срезом.

Подробный подтверждённый исходный статус и ограничения приведены в [плане](next-steps.md#что-уже-подтверждено-и-что-ещё-не-доказано). Одобрение 15 документов уже получено; оно не разрешает публиковать их содержимое в Git и не доказывает юридическую актуальность всех редакций. Пять тестовых файлов остаются отложенными до ручной загрузки.

Промпт предлагает сохранять будущие результаты в `docs/audit/reports/<date>-<shortsha>/`. Сейчас эти результаты не созданы: полный аудит будет отдельной задачей. Перед публикацией результатов убрать содержимое корпуса, личные пути и секреты; приватные приложения хранить вне Git.
