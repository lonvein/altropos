# Требования к навигатору сотрудника

Этот реестр задаёт проверяемый объём аудита. Он не подтверждает выполнение требований. Статус каждого ID и доказательства заполняются отдельным аудитом конкретного commit SHA.

## Источники и приоритет

1. **ТЗ:** локальный файл «Описание кейса для участников.docx», задача 4 «Навигатор сотрудника по внутренним регламентам». SHA-256: `2900f626832c4d2b2d6e37dd5ecfe0c55bd05e84df7596dd1feb96470bc7cfb5`. Файл не включается в Git. Ниже приведены требования и критерии, а не содержимое регламентов.
2. **Дополнения проекта:** явные уточнения пользователя в переписке и правила `AGENTS.md`. Они обозначены `PRJ-*` и не добавляют баллы к ТЗ.
3. **Проектные решения:** схемы, контракты, документация и планы реализации. Они объясняют реализацию, но не заменяют требования ТЗ и не являются доказательством готовности.

Ссылки `P7`, `P76` и подобные обозначают порядковый номер элемента `w:p` в `word/document.xml` исходного DOCX, включая пустые абзацы и абзацы таблиц. Текст внутри абзаца собирается из `w:t`. Это позволяет повторить извлечение и проверить полноту реестра без хранения исходника в репозитории.

## Правила использования реестра

- Официальные веса сохранены только у `TZ-T*` и `TZ-I*`. OCR-углы, 15+5, выбор BGE/Qwen, профиль GPU и порог Recall не объявляются прямыми условиями исходного ТЗ.
- Цели команды по Recall и задержке берутся из отдельно версионированного плана оценки. Они не считаются измеренными только потому, что записаны в документации.
- Полная матрица аудита включает каждый уникальный ID из этого файла, даже если исходник или стенд недоступен. В таком случае нужны причина, статус `NOT_VERIFIED`/`BLOCKED` и следующий способ проверки.
- Дословная цитата и положительное заключение модели сами по себе не доказывают правильность смысла. Итоговая оценка требует независимого сравнения с источником.
