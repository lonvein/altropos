# Проверка просмотра и поиска — 13 ноября 2026

## Дополнительное исправление: полный снимок и смешанные PDF

Первоначальный просмотр всех поисковых фрагментов ниже сохранён как история проверки.
Он не гарантировал полноту распознавания. Теперь HTML строится из канонических
блоков одобренного снимка, а поисковый фрагмент показывается отдельно как цитата.
Блоки привязаны к версии документа, SHA оригинала и digest опубликованных фрагментов;
повреждённый или отсутствующий снимок даёт явный отказ вместо подстановки cache.
Новые обычные загрузки сохраняют снимок до публикации индекса.

У смешанного PDF с текстовыми подписями поверх сканированного тела прежний парсер
считал текстовый слой достаточным. Теперь объединённая площадь крупных изображений
(от 40% страницы) вызывает OCR всей страницы. Малые логотипы и повторяющиеся
изображения не дают ложного суммирования площади. Недоступный OCR не позволяет
опубликовать такой документ с одними подписями. Это эвристика для крупных сканов,
а не доказательство полноты любого произвольного PDF.

Отдельно подготовлен новый pending-пакет проблемного PDF: первая страница содержит
1999 распознанных символов вместо 148. На странице 3 номер пункта требует ручной
проверки; пакет не опубликован, прежняя одобренная версия сохранена.

Отказ ответа о займе устранён общими ограничениями внутренней схемы генерации:
компактные утверждения, пары ID–дословная цитата из исходного текста при декодировании,
ограниченный список замечаний проверки. Публичные DTO, проверка дословности и
независимая смысловая проверка не ослаблены. Обрезанный JSON отклоняется.
Итоговые одиночные сценарии: займы — 44,77 с без исправления; поселение — 66,42 с
с одной попыткой исправления. Оба `partial/generated`, `supported=true`, `complete=false`.
Это не подтверждение качества всего корпуса.

Для старых публикаций миграция снимков выполняется **до обновления парсера**, в
прежнем одобренном окружении с полным совпадением fingerprint. Промежуточный
коммит с хранилищем снимков: `5b0d560`. В нём загрузчик `load_snapshot` строго
проверяет и сохраняет ранее одобренные пакеты. После проверки покрытия готовых
публикаций можно обновлять парсер. На локальной копии таким способом сохранены
1253 блока для 15 ready-документов; fingerprint не обходился. Установка сразу
нового парсера поверх старых пакетов без миграции не является корректным обновлением.
Production в рамках этой работы не обновлялся.

Итоговый прогон после всех перечисленных исправлений: **496 passed**,
Python 3.11.9; `pip check`, `git diff --check` и проверка гигиены Git прошли.
Независимая проверка обоих сохранённых ответов подтвердила все восемь дословных
цитат в действующих ready-публикациях.

## Исправления

- Карточка документа открывает полный опубликованный распознанный текст, а не первый поисковый фрагмент.
- Ссылка на цитату также показывает весь документ и выделяет выбранный фрагмент; есть переход к нему и скачивание оригинала.
- Читается только активная `ready`-публикация. Исходники и одобренные снимки не переобрабатывались.
- HTML экранирован, сохранены CSP и `nosniff`. Поисковые перекрытия сохранены и явно обозначены; исходное оформление доступно в оригинале.
- Предупреждения о непроверенном периоде действия относятся к найденным документам, показывают название. Предупреждения об отменах и редакциях сохранены.
- Назначение метаданных пояснено в интерфейсе. Требования консультации вынесены в [отдельный разбор](consultation-requirements.md).

## Воспроизведение отказа генерации

Вопрос из пользовательского примера находил правильные источники, но модель
обрывала JSON на `MAX_OUTPUT_TOKENS=768` (`finish_reason=length`). Это ошибка
генерации, а не отсутствие регламента. Технические отказы теперь получают
`unavailable` с сохранёнными источниками. Смысловой отказ и отсутствие оснований
не подменяются успешным ответом.

В отдельном локальном окружении явно установлены `MAX_OUTPUT_TOKENS=1536`
и `CONTEXT_BUDGET=1536`, при прежних `CONTEXT_SIZE=4096`,
`PROMPT_RESERVE_TOKENS=1024`, профиле 3060ti и той же модели.
Настройки других окружений и общие значения по умолчанию автоматически не менялись.
Для воспроизведения нужно явно установить обе переменные и перезапустить приложение.
Код выделяет проверке `min(MAX_OUTPUT_TOKENS, 512)` токенов как при проверке
вместимости, так и в запросе; генерация сохраняет настроенный полный лимит.
Обрезанный результат проверки по-прежнему отклоняется.

На этой конфигурации исходный вопрос завершился за **29,84 с**:
`hybrid/generated/partial`, `supported=true`, `complete=false`, `conflict=false`.
Проверены пять утверждений и девять дословных цитат опубликованных фрагментов.
В контекст вошли три из четырёх найденных фрагментов, поэтому полнота не заявляется.
Это один технический сценарий, а не оценка точности всего корпуса или SLA.
