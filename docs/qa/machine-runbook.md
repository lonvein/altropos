# Прогон на A100 и 3060 Ti

Статус на 2026-11-12: **не выполнялся**. A100 и 3060 Ti в этой среде недоступны
(`nvidia-smi` отсутствует, `/dev/nvidia*` нет), модели и веса не загружены,
интегрированное приложение отсутствует. Ниже — протокол, который нужно выполнить
на стендах. Результаты заглушек вместо модели запрещены.

## 1. Зафиксировать среду

Записать в `artifacts/runs/<run-id>/environment.txt`:

```bash
git rev-parse HEAD
git status --short
python3 --version
docker version
docker compose version
nvidia-smi
nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv
```

Дополнительно: ОС, RAM, swap, версия `llama.cpp`, ревизии GGUF/embeddings/reranker,
профиль, значения `CONTEXT_SIZE`, `CONTEXT_BUDGET`, `MAX_OUTPUT_TOKENS`,
`TOP_FRAGMENTS`, `ML_DEVICE`, `THRESHOLD_CALIBRATED`.

Секреты, токены доступа и содержимое `.env` в артефакты не попадают.

## 2. Подготовить чистый стенд

1. Остановить приложение и модельные сервисы.
2. Взять пустой `DATA_DIR` или согласованный снимок; записать его SHA-256.
3. Загрузить только разрешённые документы и дождаться `ready`.
4. Убедиться, что `needs_review` не участвует в поиске.
5. Проверить `/health`: активный профиль, LLM, ML, причины ограничений.
6. Проверить, что в поиске нет fixtures и искусственных ответов, кроме
   явно помеченного синтетического корпуса.

## 3. Настройка (20 вопросов)

1. Взять `split=setup` из `docs/qa/questions.json`.
2. Разрешить менять промпты, пороги и параметры поиска.
3. После каждого изменения фиксировать diff настроек.
4. Добиться стабильного качества, но не трогать `split=final`.
5. Записать итоговый commit и конфигурацию; заморозить их.

## 4. Финальный прогон (20 вопросов)

1. Взять `split=final`; после начала прогона настройки не менять.
2. Для каждого вопроса отправить `POST /api/ask` с `question` и `as_of`.
3. Сохранить полный JSON ответа, HTTP-код, время и ID профиля.
4. Открыть каждый `sources[].url` и убедиться, что цитата совпадает.
5. Зафиксировать статус, факты, запреты и `Recall@8`/`Recall@4`.
6. Повторить на второй машине тем же набором и той же ревизией документов.
7. Один и тот же вопрос не переспрашивать «до нужного ответа».
8. При `unavailable`/тайм-ауте писать причину, а не подставлять прошлый ответ.

## 5. Формат артефакта

```text
artifacts/runs/<run-id>/
  environment.txt
  config.txt
  data-dir.sha256
  setup/
    Q-G-S-01.json
    ...
  final/
    Q-G-S-07.json
    ...
  summary.csv
```

`summary.csv` заполняется по шаблону `docs/results.csv`. Допустимые значения
`a100_run`/`gpu3060ti_run`: `PASS`, `FAIL`, `UNAVAILABLE`, `NOT_RUN`.
Пустые поля запрещены; для `UNAVAILABLE`/`NOT_RUN` указывается причина.

## 6. Подсчёт

```text
Recall@K = число вопросов с ответом, где все expected_fragments вошли в top-K
           ---------------------------------------------------------------
                           число вопросов с ответом
```

- A100: K = 8.
- 3060 Ti: K = 4 (профиль `3060ti`) или K = 4 для `4b`.
- Статус и цитаты считаются по всем 20 финальным вопросам.
- Медиана и p95 времени — по фактическим замерам, без округления в удобную сторону.
- Если вопрос `not_found`, отсутствие источников — ожидаемо; это не снижает recall.

## 7. Остановка и перенос

1. Остановить приложение; дождаться завершения записи.
2. Выполнить checkpoint SQLite WAL.
3. Перенести всю `DATA_DIR` одним снимком (SQLite, originals, extracted, indexes).
4. На новой машине проверить хеши файлов и fingerprint embeddings.
5. Запустить приложение, открыть документ и повторить два контрольных вопроса.
6. Записать результат в чек-лист E3–E4.

## 8. Что считается блокером

- Модель отвечает, но цитаты не совпадают с фрагментами.
- `needs_review` попадает в поиск.
- Ответ `answered`, хотя verification неполный или есть конфликт.
- Результат получен из fixture/заглушки и выдан за модель.
- Для A100 и 3060 Ti указаны одинаковые числа без отдельных прогонов.
- В артефактах остались секреты, внутренние документы или персональные данные.

## 9. Текущее ограничение окружения

Локальный Python — 3.14. Закреплённый `requirements-contracts.txt`
(`pydantic==2.11.4`) на нём не собирается: PyO3 0.24 не поддерживает 3.14.
Для проверки контрактов использовался Python 3.14 с более новыми зависимостями;
это **не** штатная проверка. На стенде нужен Python 3.11–3.13 и точные версии
из `requirements-contracts.txt`. Результат текущего прогона тестов:
117 passed, но он не заменяет проверку на закреплённых версиях.
