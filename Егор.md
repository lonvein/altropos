# Егор — документы, источники и редакции

## Цель и зона ответственности

Подготовить надёжную базу регламентов для RAG: загрузить документы, извлечь текст и структуру, сохранить происхождение фрагментов, обработать редакции и импорт официального сайта.

Репозиторий: https://github.com/lonvein/altropos. Рабочая ветка: `feature/documents`. Клим реализует RAG и объединяет решения; Глеб делает интерфейс, Docker и демонстрацию. Срок — два дня.

## Первый результат

В первые два часа передай Климу 5–10 фрагментов из одного PDF, одного DOCX и одного XLSX с устойчивыми ID и адресами в оригиналах. Не жди готовности всего набора: поиск и интерфейс должны разрабатываться параллельно.

В локальной папке `Данные/данные` уже есть 20 исходных файлов. Они внутренние: не коммить их в GitHub без отдельного разрешения. Искусственные примеры для тестов помечай явно.

## Задачи

### 1. Загрузка, хранение и очередь

- Загрузка PDF, DOCX, XLSX; проверка расширения и читаемости, лимит размера из конфигурации. Имя пользователя не использовать как путь хранения: генерировать безопасный ID.
- Оригиналы хранить в `runtime/originals`, производные материалы — в `runtime/extracted`, метаданные и задания — в SQLite.
- Определять дубликаты по SHA-256. Повторная загрузка возвращает существующий документ и его состояние.
- Одна обработка одновременно. Состояния: `queued`, `processing`, `ready`, `needs_review`, `error`; предупреждения и ошибки доступны интерфейсу.
- После перезапуска незавершённое задание запускается заново, без дублирования результатов. Ошибка файла не останавливает очередь.
- Не включать документ в поиск до согласованной публикации его фрагментов и индекса через функцию Клима.

### 2. Извлечение и разбиение

| Формат | Реализация | Что сохранить |
|---|---|---|
| PDF | `pdfplumber`; OCR Tesseract rus+eng для страниц без пригодного текста | Страница с единицы, блоки и координаты, заголовки, пункты и таблицы |
| DOCX | `python-docx` | Порядок абзацев и таблиц, заголовки, нумерация, идентификаторы блоков |
| XLSX | `openpyxl` | Лист, диапазон, подписи строк/колонок, формулы и сохранённые значения |
| HTML | BeautifulSoup | Основное содержание, исходный URL, адресуемые блоки |

Формулы XLSX не пересчитывать. Если сохранённого результата нет, явно обозначать это; не подставлять ноль. Не терять заголовки таблиц и условия перед списками. При нечитаемом OCR сообщать о необходимости проверки.

Размер фрагмента: ориентир 500 токенов, максимум 800; длинные разделы — с перекрытием 80. Короткие пункты и списки сохранять целиком. Таблицы делить группами строк с повторением заголовков. Клим отвечает за окончательный бюджет контекста модели, а не ты.

### 3. Метаданные и редакции

- Хранить название, номер, дату издания, известные даты начала/окончания действия, исходный URL и дату получения.
- Связи: `amends` — изменяет; `repeals` — отменяет; `appendix` — приложение. У связи есть целевой документ, необязательный целевой раздел и признак подтверждения.
- Автоматически найденная связь — предложение до подтверждения человеком. Не считать более поздний приказ автоматической заменой предыдущего.
- Поддержать исправление метаданных администратором и проверять непротиворечивость дат. Для неизвестной актуальности сохранять явный признак, а не угадывать.

### 4. Импорт сайта

- Импорт по указанному URL только с `mipt.ru` и его поддоменов. Проверять домен корректным разбором URL, включая перенаправления; похожие домены не разрешать.
- Ограничить время и объём загрузки. Не скачивать произвольные внутренние адреса и неподдерживаемые схемы URL.
- Для страницы извлечь основной текст и список допустимых ссылок на документы. Пользователь выбирает ссылки, которые нужно импортировать.
- Сохранять снимок страницы/документа, URL и дату загрузки. Дальше использовать ту же очередь и индексирование.
- Полный обход сайта не делать.

## Контракт с Климом

Структура фрагмента:

```json
{
  "id": "стабильный идентификатор фрагмента",
  "document_id": "идентификатор документа",
  "ordinal": 0,
  "text": "текст пункта с необходимыми заголовками",
  "section": "3.2",
  "locator": {"kind": "pdf", "page": 2, "bbox": [0, 0, 100, 100]}
}
```

Варианты locator: PDF — `page` с единицы и необязательный `bbox`; DOCX — `block` с нуля; XLSX — `sheet` и `range`; HTML — `block` с нуля. В SQLite locator сериализуется в JSON. Порядок, ID и адреса должны совпадать с просмотрщиком. При изменении содержимого создаётся новая версия.

Передаёшь фрагменты в функцию Клима `index_document(document_id, fragments) -> IndexResult`. Она возвращает `mode: hybrid | bm25` и предупреждения. Статус `ready` ставится только после успешной публикации. `needs_review` не участвует в поиске до проверки. Если ML недоступен, BM25-публикация допустима только с явно сохранённым ограниченным режимом.

Клим владеет общими схемами и SQLite-слоем. Изменения таблиц и контракта сначала согласовать с ним; не создавать вторую независимую базу.

## Контракт с Глебом

Ты реализуешь backend-router документов и источников:

| Endpoint | Результат |
|---|---|
| `POST /api/documents` | Multipart-файл → `document_id`, `job_id`, `status`; при дубликате — существующий документ |
| `POST /api/import-url` | `{url, selected_urls: []}` → `job_id`; результат задания содержит допустимые ссылки и ID импортированных документов |
| `GET /api/jobs/{id}` | `id`, `status`, `error`, `result` |
| `GET /api/documents` | `{documents: [...]}` с ID, названием, состоянием, предупреждениями и метаданными |
| `PATCH /api/documents/{id}/metadata` | Название, номер, даты, `reviewed`, список связей → обновлённый документ |
| `GET /api/sources/{fragment_id}` | Безопасное HTML-представление источника с выделением фрагмента |
| `GET /api/documents/{id}/original` | Оригинал; PDF допускает открытие с `#page=N` |

Минимальная запись документа в списке: `id`, `title`, `status`, `warnings`, `metadata`. Связь в метаданных: `target_id`, `kind`, `target_section`, `confirmed`.

Ты создаёшь HTML-представление DOCX/XLSX/HTML и адреса блоков; Глеб оформляет просмотрщик и переходы к ним. Экранировать содержимое: текст документа не должен исполняться как HTML/JavaScript. Ошибки API отдавать в стандартном поле FastAPI `detail`, без внутренних путей и трассировок.

## Файлы и порядок работы

Твоя зона: `navigator/ingestion/`, `navigator/documents/`, шаблон представления источника и тесты парсеров/импорта. Глеб владеет общей страницей, стилями и `navigator/main.py`; Клим — общими конфигурацией, схемами, базой и зависимостями. Передать Глебу router для подключения, а системные зависимости OCR — для Dockerfile.

- Первые 2 часа: проверить исходники, согласовать locator и отдать первые фрагменты.
- Первый день: загрузка, парсеры трёх форматов, очередь, публикация через Клима и открытие источника.
- Второй день: OCR, импорт сайта, редакции, ошибки и проверка всего комплекта.
- Последние 3–4 часа: только исправления, результаты испытаний и документация.

Работай маленькими коммитами в `feature/documents`; PR адресуй Климу. Не меняй общий контракт без сообщения остальным. Не жди конца дня, чтобы передать работающий кусок.

## Критерии готовности и сдача

- Все 20 файлов обработаны либо имеют конкретную диагностированную ошибку; нет молча пропущенных страниц/листов.
- Есть проверки повреждённого файла, скана, дубликата, перезапуска очереди, DOCX-таблицы, XLSX с отсутствующим сохранённым значением и запрещённого URL/редиректа.
- Загрузка нового документа не требует изменения кода; ссылка открывает именно тот источник, из которого взята цитата.
- Подготовить 12 примеров для общего набора из 40: 4 OCR, 4 таблицы, 4 редакции/поправки. Для каждого — вопрос, ожидаемый статус, название и точный пункт, обязательные факты. Если реальных примеров категории нет, создать явно искусственный тестовый документ.
- Передать Глебу описание форматов, загрузки, OCR-зависимостей и ограничений для README.
- Для демонстрации показать добавление документа и переход к основанию. Не заявлять проверку на 700 документах без испытания.
